# 05 — uv (Python package & project manager) + Python 3.15

- **Date:** 2026-10-12
- **Status:** Active
- **Version installed:** uv 0.13.0 (aarch64-unknown-linux-gnu), managed CPython 3.15.0
- **Needs sudo:** No
- **Survives OS updates:** Yes (everything lives in the home folder)

## Why this way

- **Astral's standalone installer, not `cargo install`.** uv is written in Rust, but Astral provides ready-made builds. The standalone install takes seconds and supports `uv self update`. A cargo install compiles hundreds of crates on the device, can't self-update, and has to recompile for every update.
- **uv-managed Python, not the system's Python.** `/usr/bin/python3` (3.12.3) belongs to SteamOS. It changes with OS updates, and SteamOS's own tools depend on it. uv keeps its own Python builds in your home folder and picks the version each project asks for.
- **The system `python3` is left alone.** The Python install did *not* use `--default`, so plain `python3` / `python` still mean the system's 3.12. uv only added a versioned `python3.15` command. Use `uv run` in projects, or `python3.15` when you explicitly want the uv build.

## Everyday use

```bash
uv init myproject && cd myproject   # new project (pyproject.toml, .python-version, git repo)
uv add requests                      # add a dependency (creates/updates .venv and uv.lock)
uv run python main.py                # run inside the project's environment
uv run pytest                        # run tools installed in the project
uvx ruff check .                     # run a one-off tool without installing it (like npx)
uv python install 3.13               # install another Python version
uv python list --only-installed      # see installed Pythons
uv self update                       # update uv itself
```

Python 3.15.0 is very new. If a package has no prebuilt wheel for 3.15 on ARM64 yet, pin the project to an older Python with `uv python pin 3.13` (uv downloads it automatically).

VS Code finds the project's `.venv` automatically once the Python extension is installed.

## Changes made

### Installer verification

- Installer: `https://astral.sh/uv/0.13.0/install.sh`, downloaded and inspected before running.
- The installer has the archive's SHA-256 built in (`3ccfb6af6e242433eb552f7d9676abd5412c6595c497e990d9c8cb7b5bd4d2c3` for `uv-aarch64-unknown-linux-gnu.tar.gz`) and checks it after downloading. That matches GitHub's published digest for the 0.13.0 release.

### Files created

| Path | Purpose |
|---|---|
| `~/.local/bin/uv`, `~/.local/bin/uvx` | uv itself |
| `~/.config/uv/uv-receipt.json` | Install receipt; this is what makes `uv self update` work |
| `~/.local/share/uv/python/cpython-3.15-linux-aarch64-gnu/` | uv-managed Python 3.15.0 |
| `~/.local/bin/python3.15` | Symlink to the managed Python |
| `~/.cache/uv/` | Download and package cache (safe to delete; `uv cache clean`) |

## How to revert

```bash
uv cache clean
rm -rf "$(uv python dir)" "$(uv tool dir)"   # managed Pythons and uv-installed tools
rm ~/.local/bin/uv ~/.local/bin/uvx ~/.local/bin/python3.15
rm -r ~/.config/uv
# Remove the "uv / uvx tab completion" block from ~/.bashrc.
# Don't restore backups/05/bashrc.before wholesale: change 06 also added lines after it.
```

Project folders keep their own `.venv`. Delete those per project if you want.
